# Phone handling for AI voice bookings

## Intended behavior

1. The AI never asks the caller for their phone number.
2. The LiveKit SIP participant is the trusted source of caller identity. The agent reads `sip.phoneNumber` from the participant attributes. LiveKit documents this value as the caller number for inbound SIP calls and the destination number for outbound calls.
3. A per-call tool factory injects the phone into booking/get/update/cancel tool execution. The phone is not part of the LLM tool schemas.
4. `Customer.phone` is required and unique.
5. `Customer.email` is optional. Empty email values are stored as `null`.
6. Dashboard bookings still require phone, but dashboard email is optional.

## Provider integration

For a normal LiveKit SIP trunk, `sip.phoneNumber` should be available automatically. For a custom telephony provider, forward the provider caller number into LiveKit as a SIP participant attribute (for example through `headers_to_attributes` mapping to `caller.phone`) or as participant metadata. Do not accept a phone number generated by the LLM as the source of truth.

## Failure behavior

If caller phone is unavailable to the agent, the create-booking tool refuses to create the booking rather than asking the customer to dictate the phone number. The agent prompt tells the model to explain that limitation without requesting a phone number.

## Existing data

The old Customer model used a fake default phone. New customers no longer get a fake phone number. Review any existing customers using a placeholder value before production.
